Interactive architecture map

Single integrated engineering diagram. The repo sits on a VPS host behind nginx + Cloudflare, with GitHub Actions as the control plane. Recommended docker-* runtime split shown at bottom.

Workflow category distribution (v2)

17 workflows now cluster into 5 categories. The addition of lint.yml, benchmark.yml, and the workflows meta-trigger shifts the balance toward QA coverage.

Code-domain concentration (v2)

5 engineering domains now. The eval/ domain was missing from v1. Root-level config files and data/ storage added as cross-cutting concerns.

Document pipeline runtime-heavy

Inferred from src/pipelines, src/generators, src/validators, src/integrations, and translator_v3. Reinforced by validation and PDF workflows that indicate artifact-oriented stages rather than a single request/response code path.

Engineering consequences

Separate synchronous control APIs from asynchronous artifact workers. Treat validation, rendering, and format checking as queueable workloads rather than UI-coupled operations. The generate-pdf workflow proves these are independently invocable stages.

Likely responsibilities

Section transformation, prompt-backed generation, document integrity checks, translation, format normalization, PDF production, and reference verification. Cross-reference-check workflow validates inter-document consistency.

RAG / LLM routing latency-sensitive

The coexistence of rag/, llm_router/, rate_limiter/, and system_prompts/ indicates an explicit model-access subsystem, not a simple library call pattern. The rate_limiter module is wired as FastAPI middleware protecting /api/ endpoints.

Engineering consequences

Give this its own service boundary so provider credentials (Gemini API key), retries, quotas, prompt versions, and throughput metrics are decoupled from UI scaling and document batch jobs. The middleware-based rate limiter already assumes this isolation in its path-prefix design.

Likely responsibilities

Retrieval assembly (ChromaDB), provider selection (Gemini), prompt-contract enforcement, budget control via rate_limiter middleware, and backpressure management. Jurisdiction-specific system prompt selection is handled through the system_prompts/ directory.

UI surface edge-facing

webui/ is a multi-module FastAPI application, not a single file. It contains main.py (routes + auth middleware), api_chat.py (SSE streaming + RAG), api_docs.py (GitHub/GDrive/RAG document management), gdrive_ingestor.py, and an api/ package with 11 modules including autocomplete, charge mapping, FIR drafting, pipeline control, and provider management.

Engineering consequences

No direct provider secrets in the frontend. No embedded rendering pipeline in HTML. Keep it as an API client with server-side rendering. The HTTP Basic Auth middleware gates all app pages while leaving the landing page and /health endpoint public. The two-page architecture (public landing + auth-gated app) must be preserved during containerization.

Likely responsibilities

Session shell, submission forms, artifact status view, smoke-test target, operator-facing controls. The 6 HTML pages (index, app, chat, drafting, documents, jurisdiction, options) share a common navigation bar and are served as full-screen routes.

Eval / benchmark suite quality-gate

This entire domain was absent from the v1 layout. The eval/ directory contains a structured benchmarking framework with run_benchmark.py, a results dashboard.py, configurable runners/, a metrics/ collection, and a query_bank/ for standardized test queries. The benchmark.yml workflow automates execution.

Engineering consequences

This is a separate service concern. Benchmarks should not share container context with the webui or the retrieval-router. Model quality regressions can be detected independently of user traffic. The query bank represents a regression test suite for LLM outputs.

Likely responsibilities

Automated model comparison, response quality scoring, latency measurement, consistency checks, and historical result tracking. The dashboard provides a view into model performance over time.

Workflow QA coverage

The 17 workflows provide multi-layered quality assurance. Validation workflows (validate-md, validate-pdf, validate-pdf-units, cross-reference-check) run on every push. The lint workflow covers Python. lint-html-css covers the WebUI frontend. ui-smoke validates the deployed HTML pages. The benchmark workflow gates model quality.

Engineering consequences

This QA layer must remain in GitHub Actions post-migration. Container services should expose health and smoke endpoints that these workflows can hit. The ui-smoke workflow already tests the live webui, proving the pattern works for container targets too.

Runtime context detail

The application runs as a systemd service with Restart=on-failure and 5-second backoff. Uvicorn binds to localhost only, making nginx the sole external entry point. The nginx config proxies port 80 to this backend with WebSocket support, 50M upload limit, and disabled caching. Cloudflare handles TLS termination upstream. The .env file holds API keys and configuration (see private repo for variable names).

Infra lifecycle analysis

The presence of runner-lifecycle.yml, vm-provisioner.yml, vm-scheduled-guard.yml, and wake-before-run.yml indicates the system manages compute readiness and runner availability explicitly through Actions. The GitHub workflow layer is already the operator control plane and should stay that way after runtime services are containerized.

Do not move infra lifecycle semantics into arbitrary app startup scripts. Preserve the boundary: Actions orchestrate, services execute.

Infrastructure and deployment topology

This section was entirely absent from the v1 layout. The production runtime depends on a specific infrastructure chain that must be documented for any migration or handoff scenario.

Network path

User browsers connect to parselex.app which resolves through Cloudflare's CDN. Cloudflare terminates TLS (TLSv1.2/1.3 only) and proxies to the VPS origin on port 80. The VPS runs nginx which reverse-proxies to the application server (uvicorn on localhost). The entire internal path is unencrypted HTTP on localhost.

Service management

The application runs as a systemd service with Restart=on-failure and 5-second backoff. Uvicorn binds to localhost only (not 0.0.0.0), making nginx the sole external entry point. The WorkingDirectory is the git repo root, so git pull on the host directly updates the running code after a service restart.

nginx configuration

The nginx site config sets a 50M client_max_body_size for legal document uploads, disables all caching (proxy_no_cache, no-store, must-revalidate), and adds security headers (X-Frame-Options DENY, X-Content-Type-Options nosniff, X-XSS-Protection). A dedicated location /health block bypasses the main proxy configuration. WebSocket upgrade is enabled for SSE streaming.

Secrets and environment

Credentials live in the application's .env file (loaded via python-dotenv) and a GCP service account key file for GPU VM management. Authentication is handled via HTTP Basic Auth gate (credentials in .env). LLM access and GCP variables enable GPU wake/shutdown through the API endpoint. See the private repository for full variable names and paths.

Migration target matrix (v2)

webui

Thin FastAPI edge shell. Serves 7 HTML pages, 6 app routes, and proxies API calls. Holds auth middleware. Talks to internal APIs only. No direct LLM or rendering work.

core-api

Owns synchronous control path for document jobs, status handling, and upload management. Includes the api/ modules for autocomplete, charge mapping, FIR drafting, and pipeline control.

retrieval-router

Owns model access (Gemini), retrieval composition (ChromaDB), prompt policy (system_prompts/), provider selection (llm_router/), and throttling (rate_limiter/).

worker-validator

Runs heavy render, validate, smoke, and batch-oriented document tasks from src/pipelines, src/generators, and src/validators. Queueable workloads.

eval-suite

Independent benchmarking service. Contains run_benchmark.py, dashboard.py, runners/, metrics/, and query_bank/. Triggered by benchmark.yml workflow.

ops/helper jobs

Stays workflow-led. GDrive sync (gdrive_ingestor.py), helper restart, health inspection, and VM lifecycle (wake/shutdown). Uses GCP key for VM management.

Storage split

Separate immutable code (git), mutable artifacts (uploads/, results/), retrieval index (ChromaDB), and config state (.env, GCP key file) before final image hardening.

data/ directory

Repository-adjacent data storage. Holds persistent datasets used by pipelines and RAG. Must be volume-mounted into containers, not baked into images.

docs/ directory

Contains research and reporting documentation (e.g., research_reporting_options.md). Reference material, not runtime code. Can be served as static content or kept external.
